Oke, skenario yang familiar banget.

Lo bikin aplikasi e-commerce. Di local, lo nambahin kolom `phone` ke tabel `users`:

```sql
-- Local development
ALTER TABLE users ADD COLUMN phone VARCHAR(20);
```

Lo test, works fine. Lo deploy ke production.

Di production server, lo buka terminal, SSH ke VPS, login MySQL:

```bash
mysql -u root -p myapp_production

ALTER TABLE users ADD COLUMN phone VARCHAR(20);

ERROR 1060: Duplicate column name 'phone'
```

Ah sial, kolom `phone` udah ada di production dari migrate sebelumnya. Lo hapus, continue.

**3 bulan kemudian:**

Lo refactor aplikasi, rename kolom `phone` jadi `phone_number`:

```sql
ALTER TABLE users CHANGE phone phone_number VARCHAR(20);
```

Di local works. Lo deploy.

Tapi wait | lo lupa yang production kolomnya `phone_number` bukan `phone`. Lo CHANGE jadi `phone_number` lagi, sekarang ada kolom `phone_number_number`.

```sql
-- What happened:
-- Local: phone → phone_number
-- Production: phone → phone_number_number
-- Thanks, typo.
```

Sound familiar?

Managing database schema secara manual itu: **error-prone, trackable, dan messy**.

Solusinya? **Prisma ORM + Migrations**.

Di artikel ini, gue bakal tunjukin gimana Prisma bikin ngurusin database schema jadi menyenangkan. Satu command, semua environment sync.

## Apa Itu Prisma ORM?

Prisma itu **next-generation ORM** untuk Node.js dan TypeScript.

```
Traditional ORM (Sequelize, TypeORM):
| Define models di JavaScript/TypeScript
| Schema sync manual
| Migrations = separate tool

Prisma:
| Define schema di schema.prisma (declarative!)
| Generate type-safe client
| Built-in migrations
| Zero-config type safety
```

**Kenapa Prisma?**

```
Prisma benefits:
| 1. Type-safe queries | IDE autocomplete everywhere
| 2. Declarative schema | Tinggal edit file, semua sync
| 3. Built-in migrations | Version control buat schema
| 4. Auto-generated client | Nggak perlu nulis SQL manual
| 5. Migration history | Tau siapa ubah apa, kapan
```

## Setup Prisma dari Nol

Oke, sekarang praktiknya. Lo bakal setup Prisma dengan PostgreSQL.

### Step 1: Install Dependencies

```bash
npm install prisma @prisma/client
npm install -D typescript @types/node ts-node
```

### Step 2: Initialize Prisma

```bash
npx prisma init
```

Ini bakal bikin struktur:

```
prisma/
├── schema.prisma   # Schema definition
└── migrations/    # Migration files (nanti)

.env                # Environment variables
```

### Step 3: Setup Environment

```bash
# .env
DATABASE_URL="postgresql://postgres:password@localhost:5432/myapp?schema=public"
```

### Step 4: Tulis Schema

Ini bagian pentingnya | lo definisiin semua models di `schema.prisma`:

```prisma
// prisma/schema.prisma

generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

model User {
  id        Int      @id @default(autoincrement())
  name      String   @db.VarChar(100)
  email     String   @unique
  phone     String?  @db.VarChar(20)
  role      Role     @default(USER)
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  orders    Order[]
  posts     Post[]

  @@index([email])
}

enum Role {
  USER
  ADMIN
  GUEST
}

model Order {
  id        Int      @id @default(autoincrement())
  userId    Int
  total     Decimal   @db.Decimal(10, 2)
  status    OrderStatus @default(PENDING)
  createdAt DateTime @default(now())

  user      User     @relation(fields: [userId], references: [id])
  items     OrderItem[]

  @@index([userId])
  @@index([status])
}

enum OrderStatus {
  PENDING
  PAID
  SHIPPED
  COMPLETED
  CANCELLED
}

model OrderItem {
  id        Int    @id @default(autoincrement())
  orderId   Int
  productId Int
  quantity  Int
  price     Decimal @db.Decimal(10, 2)

  order     Order  @relation(fields: [orderId], references: [id])
  product   Product @relation(fields: [productId], references: [id])

  @@index([orderId])
}

model Product {
  id          Int       @id @default(autoincrement())
  name        String    @db.VarChar(255)
  description String?   @db.Text
  price       Decimal   @db.Decimal(10, 2)
  stock       Int       @default(0)
  createdAt   DateTime  @default(now())
  updatedAt   DateTime  @updatedAt

  items       OrderItem[]

  @@index([price])
}

model Post {
  id        Int      @id @default(autoincrement())
  title     String   @db.VarChar(255)
  content   String   @db.Text
  authorId  Int
  published Boolean  @default(false)
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  author    User     @relation(fields: [authorId], references: [id])

  @@index([authorId])
}
```

**Perhatiin syntax-nya:**
- `Int`, `String`, `Boolean` | type dasar
- `@id` | primary key
- `@default(autoincrement())` | auto-increment
- `@default(now())` | timestamp auto
- `@unique` | unique constraint
- `@relation` | foreign key
- `?` | optional field
- `enum` | predefined values

## Generate Client dan Push Schema

Sekarang lo bakal sync schema ke database.

### Method 1: prisma db push (Development Only)

Ini langsung push schema ke database tanpa migration:

```bash
npx prisma db push
```

**Use case:** Development cepat, prototyping, atau nggak mau ribet dengan migrations.

**⚠️ Warning:** Ini overwrite existing schema! Jangan dipake di production.

### Method 2: prisma migrate (Recommended)

Ini bikin migration files yang bisa di-track dan di-deploy:

```bash
npx prisma migrate dev --name init_schema
```

Output:

```
Environment variables loaded from .env
Prisma schema loaded from prisma/schema.prisma
Datasource db: postgresql

Applying migration `20240115_000000_init_schema`

Your database is now in sync with your schema.
```

Ini bikin:
1. Migration file di `prisma/migrations/`
2. Execute migration ke database
3. Generate Prisma Client

```bash
# Output:
```

## Pakai Prisma Client di Code

Sekarang gimana cara pakenya di aplikasi.

### Setup Prisma Client

```typescript
// src/lib/prisma.ts
import { PrismaClient } from '@prisma/client';

const prisma = new PrismaClient();

export default prisma;
```

### CRUD Operations

```typescript
// src/services/user.service.ts
import prisma from '../lib/prisma';
import { Role } from '@prisma/client';

// Create user
async function createUser(data: {
  name: string;
  email: string;
  phone?: string;
  role?: Role;
}) {
  const user = await prisma.user.create({
    data: {
      name: data.name,
      email: data.email,
      phone: data.phone,
      role: data.role || Role.USER,
    },
  });

  return user;
}

// Get user by ID
async function getUserById(id: number) {
  const user = await prisma.user.findUnique({
    where: { id },
    include: {
      orders: true,
      posts: {
        where: { published: true },
      },
    },
  });

  return user;
}

// Get user by email
async function getUserByEmail(email: string) {
  const user = await prisma.user.findUnique({
    where: { email },
  });

  return user;
}

// Update user
async function updateUser(id: number, data: {
  name?: string;
  phone?: string;
}) {
  const user = await prisma.user.update({
    where: { id },
    data,
  });

  return user;
}

// Delete user
async function deleteUser(id: number) {
  await prisma.user.delete({
    where: { id },
  });
}

// List users with pagination
async function listUsers(page: number = 1, limit: number = 10) {
  const skip = (page - 1) * limit;

  const [users, total] = await Promise.all([
    prisma.user.findMany({
      skip,
      take: limit,
      orderBy: { createdAt: 'desc' },
      select: {
        id: true,
        name: true,
        email: true,
        role: true,
        createdAt: true,
      },
    }),
    prisma.user.count(),
  ]);

  return {
    data: users,
    pagination: {
      page,
      limit,
      total,
      totalPages: Math.ceil(total / limit),
    },
  };
}
```

```typescript
const usersWithOrders = await prisma.user.findMany({
```

## Change Schema: Migration Workflow

Nah, ini bagian powerful-nya. Lo ubah schema, Prisma generate migration.

### Scenario: Tambah Kolom Baru

Lo mau tambah kolom `avatar_url` ke tabel `User`.

**Step 1: Edit Schema**

```prisma
// prisma/schema.prisma
model User {
  id         Int      @id @default(autoincrement())
  name       String   @db.VarChar(100)
  email      String   @unique
  phone      String?  @db.VarChar(20)
  avatarUrl  String?  @db.VarChar(500)  // ← Tambahin ini
  role       Role     @default(USER)
  createdAt  DateTime @default(now())
  updatedAt  DateTime @updatedAt

  orders     Order[]
  posts      Post[]
}
```

**Step 2: Create Migration**

```bash
npx prisma migrate dev --name add_avatar_url_to_user
```

Output:

```
Environment variables loaded from .env
Prisma schema loaded from prisma/schema.prisma
Datasource db: postgresql

Created migration file: prisma/migrations/20240115_000001_add_avatar_url_to_user/migration.sql

Applying migration `20240115_000001_add_avatar_url_to_user`

Your database is now in sync with your schema.
```

**Generated SQL:**

```sql
-- prisma/migrations/20240115_000001_add_avatar_url_to_user/migration.sql

-- AlterTable
ALTER TABLE "User" ADD COLUMN "avatarUrl" VARCHAR(500);
```

### Scenario: Rename Kolom

Lo mau rename `phone` jadi `phone_number`.

**Step 1: Edit Schema**

```prisma

  name        String   @db.VarChar(100)
  email       String   @unique
  phoneNumber String?  @db.VarChar(20)  // ← Ubah dari phone ke phoneNumber
  avatarUrl   String?  @db.VarChar(500)

  updatedAt   DateTime @updatedAt
```

**Step 2: Create Migration**

```bash
npx prisma migrate dev --name rename_phone_to_phone_number
```

**Generated SQL:**

```sql

```

## Deploy ke Production

Ini bagian yang gue suka. Deploy ke production tinggal satu command.

### Setup Production Database

```bash
# SSH ke VPS
ssh user@your-server.com

# Setup PostgreSQL
sudo -u postgres psql

CREATE DATABASE myapp_production;
CREATE USER myapp WITH ENCRYPTED PASSWORD 'strong_password';
GRANT ALL PRIVILEGES ON DATABASE myapp_production TO myapp;

\q
```

### Setup Environment Production

```bash
# .env.production
DATABASE_URL="postgresql://myapp:strong_password@localhost:5432/myapp_production?schema=public"
```

### Deploy Migration

```bash
# Pull schema changes dari Git
git pull origin main

# Install dependencies
npm ci

# Generate Prisma Client
npx prisma generate

# Deploy migrations (IMPORTANT!)
npx prisma migrate deploy
```

Output:

```
Environment variables loaded from .env
Prisma schema loaded from prisma/schema.prisma
Datasource db: postgresql

Found 3 migrations:
  20240115_000000_init_schema
  20240115_000001_add_avatar_url_to_user
  20240115_000002_rename_phone_to_phone_number

Applying migrations:
  20240115_000000_init_schema ... already applied
  20240115_000001_add_avatar_url_to_user ... already applied
  20240115_000002_rename_phone_to_phone_number ... applying ... applied

All migrations have been applied successfully.
```

**Selesai!** Tidak ada ALTER TABLE manual. Tidak ada typo. Tidak ada forgot to run script.

### Rollback Migration

Kalo lo mau undo migration:

```bash
# Rollback last migration
npx prisma migrate resolve --rolled-back 20240115_000002_rename_phone_to_phone_number
```

**⚠️ Warning:** Ini cuma undo migration record, nggak execute DOWN migrations. Lo harus bikin sendiri kalo butuh.

```dockerfile

COPY package*.json ./

```

```yaml
# docker-compose.yml
services:
  api:
    build: .
    depends_on:
      db:
        condition: service_healthy
    environment:
      DATABASE_URL: postgresql://postgres:password@db:5432/myapp

  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_PASSWORD: password
      POSTGRES_DB: myapp
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 5s
      timeout: 5s
      retries: 5

  migrate:
    build: .
    command: npx prisma migrate deploy
    depends_on:
      db:
        condition: service_healthy
    environment:
      DATABASE_URL: postgresql://postgres:password@db:5432/myapp
```

Run:

```bash
docker-compose up -d migrate
docker-compose up -d api
```

## Prisma dengan MySQL

Prisma support MySQL juga!

```prisma
// prisma/schema.prisma
datasource db {
  provider = "mysql"
  url      = env("DATABASE_URL")
}

model User {
  id        Int      @id @default(autoincrement())
  name      String   @db.VarChar(100)
  email     String   @unique @db.VarChar(255)
  phone     String?  @db.VarChar(20)
  createdAt DateTime @default(now()) @map("created_at")
  updatedAt DateTime @updatedAt @map("updated_at")

  orders    Order[]  @relation("UserOrders")
  posts     Post[]   @relation("AuthorPosts")

  @@map("users")
}
```

MySQL specific types:
- `@db.VarChar(255)` | VARCHAR
- `@db.Text` | TEXT
- `@db.Int` | INT
- `@db.DateTime` | DATETIME
- `@db.Decimal(10, 2)` | DECIMAL

## Best Practices

### 1. Jangan Edit Migration Files Manual

```bash
# ❌ BAD
# Edit migration SQL langsung di prisma/migrations/

# ✅ GOOD
# Edit schema.prisma
# Buat migration baru
npx prisma migrate dev --name fix_something
```

### 2. Commit Migrations ke Git

```bash
git add prisma/migrations/
git commit -m "feat: add user avatar and phone fields"

git push origin main
```

### 3. Environment Variables yang Benar

```bash
# .env (Development)
DATABASE_URL="postgresql://postgres:password@localhost:5432/myapp_dev?schema=public"

# .env.production (JANGAN COMMIT!)

```

### 4. Validate Schema Sebelum Build

```bash
# Check schema errors
npx prisma validate

# Format schema
npx prisma format
```

### 5. Reset Database (Development Only!)

```bash
# ⚠️ WARNING: Hapus semua data dan recreate
npx prisma migrate reset

# Confirm prompt:
# This will DELETE ALL DATA in the "myapp" database. Are you sure? [y/N]
```

## Troubleshooting Common Issues

### Issue 1: Migration Failed

```bash
# Error:
# Migration failed because its formation or constraints on the
# database are not yet fully implemented

# Penyebab:
# Migration sebelumnya gagal/terputus

# Solusi:
# Reset migrations (development only!)
npx prisma migrate reset
```

### Issue 2: Schema Drift

```bash
# Error:
# Prisma schema and database are out of sync

# Penyebab:
# Database diubah manual di luar Prisma

# Solusi:
# Sync dari database ke schema
npx prisma db pull

# Atau push schema ke database (overwrite!)
npx prisma db push
```

### Issue 3: Prisma Client Outdated

```bash
# Error:
# PrismaClient initialization error

# Penyebab:
# Schema berubah tapi client belum diregenerate

# Solusi:
npx prisma generate
```
