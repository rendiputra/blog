Oke, skenario yang familiar.

Lo punya aplikasi yang jalan di 5 containers Docker. Tiba-tiba user complaint | "Bang, ada error di checkout!"

Lo buka terminal:

```bash
# Cek logs container 1
docker logs container-api-1 2>&1 | grep error

# Cek logs container 2
docker logs container-api-2 2>&1 | grep error

# Cek logs container 3
docker logs container-api-3 2>&1 | grep error

# Cek logs container worker
docker logs container-worker 2>&1 | grep error

# Cek logs nginx
docker logs container-nginx 2>&1 | grep error
```

Lo scroll sana-sini, switch tab, copy-paste. 10 menit later, lo nemu errornya di container-api-2.

**Masalahnya:** Lo harus login ke 5 tempat berbeda cuma buat nyari log. Dan ini cuma 1 server. Gimana kalo 10 servers?

Lo butuh **centralized logging system**.

Di artikel ini, gue bakal tunjukin cara setup **Grafana Loki** atau **ELK Stack** buat centralized logging. Lo bakal bisa:

- Nyari log dari semua containers dalam 1 dashboard
- Filter by time, container name, error level
- Search dengan regex
- Visualize log patterns
- Alert pas ada error tertentu

Let's go!

## Kenapa Lo Butuh Centralized Logging?

Oke, pertama lo harus paham kenapa ini penting.

### Problem Tanpa Centralized Logging

```
Tanpa Centralized Logging:
| Container 1 | Logs di terminal / file terpisah
| Container 2 | Logs di terminal / file terpisah
| Container 3 | Logs di terminal / file terpisah
| Server 1 | SSH, cek manually
| Server 2 | SSH, cek manually
| Server 3 | SSH, cek manually

Problems:
| 1. Must login ke banyak tempat
| 2. Logs ilang pas container restart
| 3. Can't search across all containers
| 4. No historical context
| 5. Debugging = nightmare
```

### Solution: Centralized Logging

```
Dengan Centralized Logging:
┌─────────────────────────────────────────────────────────────┐
│                      Grafana Dashboard                         │
│                                                              │
│   ┌─────────────────────────────────────────────────────┐   │
│   │ Search: "error" + Filter: container=api + time=1hr │   │
│   │                                                      │   │
│   │ Log entries:                                         │   │
│   │ [10:23:45] container-api-1 | ERROR | User checkout  │   │
│   │ [10:23:46] container-api-2 | ERROR | DB timeout   │   │
│   │ [10:23:47] container-worker | WARN  | Retry...      │   │
│   └─────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
                              │
                    ┌─────────┴─────────┐
                    │                     │
          ┌─────────▼─────────┐ ┌───────▼────────┐
          │   Loki / ES       │ │  Grafana        │
          │   (Log Storage)   │ │  (Dashboard)    │
          └───────────────────┘ └────────────────┘
                    │
     ┌──────────────┼──────────────┐
     │              │              │
┌────▼────┐  ┌─────▼────┐  ┌────▼────┐
│Container 1│ │Container 2│  │Container 3│
└───────────┘ └───────────┘ └───────────┘
```

**Benefits:**
- 1 dashboard buat semua logs
- Real-time log streaming
- Powerfull search
- Historical data
- Alerting

## Pilihan: Loki vs ELK

Lo punya 2 opsi utama:

```
Grafana Loki:
| Pros:
|   - Simpler setup
|   - Lower resource usage
|   - Integrates seamlessly dengan Grafana
|   - Label-based indexing (faster queries)
| Cons:
|   - Fitur search没那么 powerful dibanding ES
|   - Less mature ecosystem

ELK Stack (Elasticsearch + Logstash + Kibana):
| Pros:
|   - Full-text search yang powerful
|   - More mature
|   - Rich visualization
| Cons:
|   - Heavy (banyak RAM needed)
|   - Complex setup
|   - Resource intensive
```

**Rekomendasi gue:**

```
Development / Small scale | Grafana Loki (simple, lightweight)
Production / Large scale | ELK (powerful, scalable)
```

Di artikel ini, gue bakal cover keduanya.

### Docker Compose Setup

```yaml
# docker-compose.monitoring.yml
version: '3.8'

services:
  # Grafana Dashboard
  grafana:
    image: grafana/grafana:latest
    container_name: grafana
    ports:
      - "3000:3000"
    environment:
      - GF_SECURITY_ADMIN_USER=admin
      - GF_SECURITY_ADMIN_PASSWORD=admin123
      - GF_USERS_ALLOW_SIGN_UP=false
    volumes:
      - grafana_data:/var/lib/grafana
      - ./grafana/provisioning:/etc/grafana/provisioning
      - ./grafana/dashboards:/var/lib/grafana/dashboards
    depends_on:
      - loki
    networks:
      - monitoring

  # Loki Log Aggregator
  loki:
    image: grafana/loki:latest
    container_name: loki
    ports:
      - "3100:3100"
    command: -config.file=/etc/loki/local-config.yaml
    volumes:
      - loki_data:/loki
      - ./loki-config.yaml:/etc/loki/local-config.yaml:ro
    networks:
      - monitoring

  # Promtail Log Collector (for host logs)
  promtail:
    image: grafana/promtail:latest
    container_name: promtail
    volumes:
      - /var/log:/var/log:ro
      - ./promtail-config.yaml:/etc/promtail/config.yaml:ro
    command: -config.file=/etc/promtail/config.yaml
    networks:
      - monitoring

  # Docker driver for container logs (runs as plugin)
  # Ini akan ng收集 semua container logs otomatis

networks:
  monitoring:
    driver: bridge

volumes:
  grafana_data:
  loki_data:
```

### Logstash Pipeline

```ruby
# logstash/pipeline/logstash.conf
input {
  beats {
    port => 5044
  }

  # Also accept logs via HTTP
  http {
    port => 8080
    codec => json
  }
}

filter {
  # Parse JSON logs
  if [message] =~ /^\{/ {
    json {
      source => "message"
      target => "parsed"
    }
  }

  # Add timestamp if not present
  if ![parsed][timestamp] {
    mutate {
      add_field => { "[@metadata][timestamp]" => "%{+YYYY-MM-dd'T'HH:mm:ss.SSSZ}" }
    }
  }

  # Extract fields from parsed JSON
  if [parsed] {
    mutate {
      rename => {
        "[parsed][level]" => "log_level"
        "[parsed][message]" => "log_message"
        "[parsed][service]" => "service_name"
        "[parsed][trace_id]" => "trace_id"
        "[parsed][user_id]" => "user_id"
      }
    }
  }

  # Handle Docker container logs
  if [container] {
    mutate {
      add_field => {
        "container_name" => "%{[container][name]}"
        "container_image" => "%{[container][image]"
      }
    }
  }

  # Categorize by log level
  if [log_level] {
    if [log_level] =~ /error|Error|ERROR/ {
      mutate {
        add_tag => ["error"]
      }
    }
    if [log_level] =~ /warn|Warn|WARN/ {
      mutate {
        add_tag => ["warning"]
      }
    }
  }
}

output {
  elasticsearch {
    hosts => ["elasticsearch:9200"]
    index => "logs-%{+YYYY.MM.dd}"
  }

  # Also output to stdout for debugging
  stdout {
    codec => rubydebug
  }
}
```

## Search Logs di Grafana

Nah, sekarang bagian yang seru | gimana search logs.

### Basic Search

```
# Di Grafana Explore (Loki):

# Search semua logs
{job="docker"}

# Filter by container name
{container_name=~"api-.*"}

# Filter by error level
{container_name=~"api.*"} |= "ERROR"

# Filter by multiple conditions
{container_name=~"api.*"} |= "ERROR" != "timeout"

# Regex search
{container_name=~"api.*"} |~ "user_[0-9]+"
```

**Operators:**
```
|= Contains (case-sensitive)
|!= Does not contain
|~ Regex match
!~ Regex does not match
```

### LogQL: Loki Query Language

```logql
# Count errors per minute
sum by (container_name) (rate({container_name=~"api.*"} |~ "ERROR"[5m]))

# Top 10 containers by log volume
topk(10, sum by (container_name) (count_over_time({job="docker"}[1h])))

# Error rate over time
sum by (level) (rate({container_name=~"api.*"} | json | level="error"[5m]))

# Slow requests (> 1 second)
{container_name=~"api.*"} | json | duration > 1000

# User-specific logs
{container_name=~"api.*"} | json | user_id="12345"
```

```
# All logs
*

# Specific field
level:ERROR

# Multiple conditions
level:ERROR AND service:api

service:api*

```

```yaml
            model:
              expr: sum(rate({container_name=~"api.*"} |~ "ERROR"}[5m])) > 0
              refId: A
          - refId: B
            relativeTimeRange:
              from: 300
              to: 0
            datasourceUid: __expr__
            model:
              conditions:
                - evaluator:
                    params:
                      - 0
                    type: gt
                  operator:
                    type: and
                  query:
                    params:
                      - B
                  reducer:
                    type: last
              datasourceUid: __expr__
              expression: A
              type: threshold
              refId: B
          - refId: C
            relativeTimeRange:
              from: 300
              to: 0
            datasourceUid: __expr__
            model:
              expression: B
              type: threshold
```

## Structured Logging Best Practices

Ini yang penting | lo harus logging dalam format yang searchable.

### Format yang Benar

```javascript
// ❌ BAD: Plain text logs
console.log('User logged in');
console.log('Error: connection timeout');
console.log('Processing order 12345');

// ✅ GOOD: Structured JSON logs
console.log(JSON.stringify({
  timestamp: new Date().toISOString(),
  level: 'info',
  message: 'User logged in',
  userId: '12345',
  ip: '192.168.1.1',
  userAgent: 'Mozilla/5.0...'
}));

console.log(JSON.stringify({
  timestamp: new Date().toISOString(),
  level: 'error',
  message: 'Connection timeout',
  service: 'payment-service',
  error: {
    name: 'TimeoutError',
    message: 'Connection refused',
    stack: error.stack
  },
  requestId: 'req-12345'
}));
```

### Logging Levels

```
FATAL | System down, immediate action needed
ERROR | Error yang affecting request/user
WARN  | Warning, tapi process continues
INFO  | Normal operation events
DEBUG | Detailed debugging information
TRACE | Very detailed, for development only
```

### Winston Logger Setup

```javascript
// src/utils/logger.js
const winston = require('winston');

const logger = winston.createLogger({
  level: process.env.LOG_LEVEL || 'info',
  format: winston.format.combine(
    winston.format.timestamp(),
    winston.format.errors({ stack: true }),
    winston.format.json()
  ),
  defaultMeta: {
    service: process.env.SERVICE_NAME || 'api',
    version: process.env.npm_package_version,
    environment: process.env.NODE_ENV
  },
  transports: [
    // Console output
    new winston.transports.Console({
      format: winston.format.combine(
        winston.format.colorize(),
        winston.format.simple()
      )
    })
  ]
});

// Add file transport for production
if (process.env.NODE_ENV === 'production') {
  logger.add(new winston.transports.File({
    filename: 'logs/error.log',
    level: 'error'
  }));
  logger.add(new winston.transports.File({
    filename: 'logs/combined.log'
  }));
}

module.exports = logger;
```

### Usage

```javascript
// src/services/user.service.js
const logger = require('../utils/logger');

async function createUser(data) {
```

- Grafana buat dashboard
- Docker logging driver buat container logs

**ELK Stack:**
- Elasticsearch buat storage
- Logstash buat parse logs
- Kibana buat dashboard
- Filebeat buat collect logs

**Search Capabilities:**
- Loki: LogQL buat filter dan aggregate
- Kibana: KQL buat full-text search

**Benefits:**

```
Dengan Centralized Logging:
| 1. Single source of truth | Semua logs di satu tempat
| 2. Powerful search | Filter by container, time, error level
| 3. Historical data | Liat logs dari days/weeks ago
| 4. Alerting | Notification pas ada error tertentu
| 5. Correlation | Trace error across services
| 6. Debugging | Past errors jadi lebih gampang dilacak

Setup process:
| 1. Deploy Loki/ELK dengan Docker
| 2. Setup log collector (Promtail/Filebeat)
| 3. Configure structured logging di app
| 4. Setup Grafana/Kibana dashboard
| 5. Setup alerts untuk critical errors
| 6. Enjoy peaceful debugging
```

**The Takeaway:**

Centralized logging itu bukan luxury | it's essential buat production applications. Lo bisa debug errors dalam hitungan detik, bukan scroll through 10 terminal tabs.

Sekarang pas ada error, lo tinggal:
1. Buka Grafana/Kibana
2. Search error message
3. Filter by time dan container
4. Done | lo tau root cause dalam 1 menit

Gue recommend mulai dengan Grafana Loki karena lebih simple dan lightweight. Kalo butuh fitur yang lebih advanced, baru migrate ke ELK.

Giliran lu | setup centralized logging di project lu. Starting with Loki for simplicity, expand dari situ.
