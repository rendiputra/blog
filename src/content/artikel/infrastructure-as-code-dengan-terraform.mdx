Oke, skenario yang familiar.

Lo mau setup server production. Langkah-langkahnya:

```
Dashboard AWS:
| 1. Klik "Launch Instance"
| 2. Pilih AMI (Ubuntu 22.04)
| 3. Pilih instance type (t3.medium)
| 4. Konfigurasi network (VPC, subnet)
| 5. Add storage (50GB gp3)
| 6. Add tags (Name: production-server)
| 7. Configure security group
| 8. Review and launch
| 9. Select key pair
| 10. Klik launch
| 11. Wait for instance...
| 12. Copy public IP
| 13. SSH to server
| 14. Install packages
| 15. Configure...

Time spent: 45 minutes, mostly clicking
```

**3 bulan kemudian:**

Lo mau setup environment yang sama untuk staging. Lo harus:
1. Buka dashboard AWS lagi
2. Klik-klik lagi
3. Hops, lupa enable auto-scaling di staging
4. Nggak sama persis dengan production
5. 45 menit later | nggak identical dengan production

**1 tahun kemudian:**

Lo punya 5 servers. Documentation? Nggak ada. Konfigurasi? Cuma ada di dashboard. Setup baru? Gotta click everything again.

Sound familiar?

Lo butuh cara yang lebih baik. Solusinya? **Infrastructure as Code (IaC)**.

Di artikel ini, gue bakal tunjukin gimana Terraform bikin lo bisa define seluruh infrastruktur dalam code. Commit ke Git, review changes, dan tinggal `terraform apply`. No more clicking.

Let's go!

## Kenapa Manual Provisioning Itu Problem?

Oke, pertama lo harus paham kenapa manual provisioning itu problematic.

### 1. Not Reproducible

```
Lo setup server A dengan:
| - Ubuntu 22.04
| - 4GB RAM
| - 50GB SSD
| - Security group: port 22, 80, 443

Server B harus sama? Gotta click everything again.
Difference? Probably yes.
```

### 2. No Version Control

```
Dashboard AWS:
| - Server config from 3 months ago
| - "apa sih yang gue ubah?"
| - "kenapa ini diset gini?"
| - Nobody knows.

Git history? Nggak ada.
```

### 3. No Review Process

```
Team member A: "gue ubah security group ya"
Team member B: *doesn't know*
Team member C: *doesn't know*
Team member A: " gue lupa bilang"

Result: Chaos.
```

### 4. No Rollback

```
Lo upgrade instance type:
| t3.medium → t3.large

Something breaks.
Rollback? Gotta remember original settings.
```

## Apa Itu Infrastructure as Code?

IaC itu practice di mana lo define dan manage infrastruktur dengan **code**, bukan dengan **manual clicking**.

```
Traditional:
| Dashboard → Click → Click → Click → Server Created

IaC:
| Code (Terraform) → terraform apply → Server Created
```

### Benefits

```
IaC benefits:
| 1. Reproducible | Same config, every time
| 2. Versioned | Git history of changes
| 3. Reviewable | PR review before apply
| 4. Rollback | git checkout previous version
| 5. Documentation | Code is documentation
| 6. Automation | CI/CD pipeline possible
| 7. Collaboration | Team bisa kerja bareng
```

## Terraform vs Alternatives

Ada beberapa IaC tools:

```
| Tool | Provider | Characteristics |
|------|----------|------------------|
| Terraform | Multi-cloud | HCL language, provider-based |
| Pulumi | Multi-cloud | Real programming language |
| AWS CDK | AWS only | TypeScript, Python, etc |
| Ansible | Config management | Imperative, agent-based |
| CloudFormation | AWS only | JSON/YAML, AWS native |

Terraform: Best balance between capability dan multi-cloud support.
```

**Kenapa Terraform?**
- Multi-cloud support (AWS, GCP, Azure, DigitalOcean, dll)
- Declarative | lo specify what, Terraform figure out how
- Provider ecosystem | hampir semua cloud providers support
- State management | track what's deployed
- Large community

## Basic Terraform Concepts

### Providers

Provider adalah plugin yang ngurusin resource di specific cloud/infrastructure.

```hcl
# main.tf

terraform {
  required_version = ">= 1.0"

  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
  }
}

provider "aws" {
  region = var.aws_region
}
```

### Resources

Resource adalah infrastruktur yang lo mau buat.

```hcl
resource "aws_instance" "web" {
  ami           = var.ami_id
  instance_type = var.instance_type

  tags = {
    Name        = "production-web-server"
    Environment = var.environment
  }
}
```

### Variables

Variable bikin config lo reusable dan customizable.

```hcl
# variables.tf

variable "aws_region" {
  description = "AWS region"
  type        = string
  default     = "ap-southeast-1"
}

variable "environment" {
  description = "Environment name"
  type        = string
  default     = "production"
}

variable "instance_type" {
  description = "EC2 instance type"
  type        = string
  default     = "t3.medium"
}
```

### Outputs

Output bikin lo bisa liat hasil dari Terraform apply.

```hcl
# outputs.tf

output "instance_public_ip" {
  description = "Public IP address of the instance"
  value       = aws_instance.web.public_ip
}

output "instance_id" {
  description = "ID of the instance"
  value       = aws_instance.web.id
}
```

### 1. Setup Providers dan Backend

```hcl
# providers.tf

terraform {
  required_version = ">= 1.0"

  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
  }

  # Terraform state remote storage (recommended)
  backend "s3" {
    bucket         = "my-terraform-state"
    key            = "prod/terraform.tfstate"
    region         = "ap-southeast-1"
    encrypt        = true
    dynamodb_table = "terraform-locks"
  }
}

provider "aws" {
  region = var.aws_region

  default_tags {
    tags = {
      ManagedBy = "Terraform"
      Project   = var.project_name
    }
  }
}
```

### 2. Create VPC

```hcl
# modules/vpc/main.tf

resource "aws_vpc" "main" {
  cidr_block           = var.vpc_cidr
  enable_dns_hostnames = true
  enable_dns_support   = true

  tags = {
    Name = "${var.project}-vpc"
  }
}

resource "aws_subnet" "public" {
  count                   = length(var.availability_zones)
  vpc_id                  = aws_vpc.main.id
  cidr_block              = cidrsubnet(var.vpc_cidr, 8, count.index)
  availability_zone        = var.availability_zones[count.index]
  map_public_ip_on_launch = true

  tags = {
    Name = "${var.project}-public-subnet-${count.index + 1}"
    Type = "public"
  }
}

resource "aws_subnet" "private" {
  count             = length(var.availability_zones)
  vpc_id            = aws_vpc.main.id
  cidr_block        = cidrsubnet(var.vpc_cidr, 8, count.index + 10)
  availability_zone = var.availability_zones[count.index]

  tags = {
    Name = "${var.project}-private-subnet-${count.index + 1}"
    Type = "private"
  }
}

resource "aws_internet_gateway" "main" {
  vpc_id = aws_vpc.main.id

  tags = {
    Name = "${var.project}-igw"
  }
}

resource "aws_route_table" "public" {
  vpc_id = aws_vpc.main.id

  route {
    cidr_block = "0.0.0.0/0"
    gateway_id = aws_internet_gateway.main.id
  }

  tags = {
    Name = "${var.project}-public-rt"
  }
}

resource "aws_route_table_association" "public" {
  count          = length(aws_subnet.public)
  subnet_id      = aws_subnet.public[count.index].id
  route_table_id = aws_route_table.public.id
}
```

```hcl
# modules/vpc/variables.tf
```

### 3. Create EC2 Instance

```hcl
# modules/ec2/main.tf

resource "aws_instance" "web" {
  ami                    = var.ami_id
  instance_type         = var.instance_type
  subnet_id             = var.subnet_id
  vpc_security_group_ids = var.security_group_ids
  key_name              = var.key_name

  user_data = templatefile("${path.module}/user_data.sh", {
    environment = var.environment
  })

  root_block_device {
    volume_size = var.root_volume_size
    volume_type = "gp3"
    encrypted   = true
  }

  tags = {
    Name = "${var.project}-web-server"
  }
}

resource "aws_security_group" "web" {
  name        = "${var.project}-web-sg"
  description = "Security group for web server"
  vpc_id      = var.vpc_id

  ingress {
    description = "HTTP"
    from_port   = 80
    to_port     = 80
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }

  ingress {
    description = "HTTPS"
    from_port   = 443
    to_port     = 443
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }

  ingress {
    description = "SSH"
    from_port   = 22
    to_port     = 22
    protocol    = "tcp"
    cidr_blocks = [var.allowed_ssh_cidr]
  }

  egress {
    description = "All outbound"
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }

  tags = {
    Name = "${var.project}-web-sg"
  }
}
```

## Terraform Workflow

Sekarang gimana cara pakainya.

### Step 1: Initialize

```bash
# Download providers dan setup backend
terraform init

# Output:
# Initializing the backend...
# Initializing provider plugins...
# - Finding hashicorp/aws versions matching "~> 5.0"...
# - Installing hashicorp/aws v5.x.x...
# Terraform has been successfully initialized!
```

### Step 2: Plan (Preview Changes)

```bash
# Liat apa yang bakal di-create/update/destroy
terraform plan

# Output:
# Terraform will perform the following actions:
#
#   # aws_vpc.main will be created
#   + resource "aws_vpc" "main" {
#   +   cidr_block           = "10.0.0.0/16"
#   +   enable_dns_hostnames = true
#   +   ...
#   }
#
#   # aws_instance.web will be created
#   + resource "aws_instance" "web" {
#   +   ami                  = "ami-xxx"
#   +   instance_type        = "t3.medium"
#   +   ...
#   }
#
# Plan: 8 to add, 0 to change, 0 to destroy.
```

### Step 3: Apply (Create Infrastructure)

```bash
# Apply changes
terraform apply

# Terraform will show plan again, type "yes" to confirm
# Do you want to perform these actions?
#   Terraform will perform the actions described above.
#   Enter a value: yes

# Terraform apply...
# aws_vpc.main: Creating...
# aws_vpc.main: Creation complete after 30s
# aws_instance.web: Creating...
# aws_instance.web: Creation complete after 2m

# Apply complete! Resources: 8 added, 0 changed, 0 destroyed.

# Outputs:
# web_server_public_ip = "54.123.456.789"
# database_endpoint = "myapp-db.xxx.region.rds.amazonaws.com:5432"
```

### Step 4: Destroy (Teardown)

```bash
# Hapus semua infrastructure
terraform destroy

# Terraform will show what will be destroyed
# Do you want to perform these actions?
#   Enter a value: yes

# Destroy complete! Resources: 8 destroyed.
```

## State Management

Terraform nyimpen state di file `terraform.tfstate`. Ini track apa yang udah di-deploy.

### Local State (Development)

```hcl
# Development only!
terraform {
  backend "local" {
    path = "terraform.tfstate"
  }
}
```

### Remote State (Production - Recommended)

```hcl
terraform {
  backend "s3" {
    bucket = "my-terraform-state"
    key    = "prod/terraform.tfstate"
    region = "ap-southeast-1"
    encrypt = true
    dynamodb_table = "terraform-locks"
  }
}
```

**Benefits remote state:**
- Team bisa collaborate
- State nggak ilang kalo local machine crash
- State locking | prevents concurrent apply
- Encryption at rest

## Team Workflow

Ini cara kerja tim dengan Terraform.

### 1. Branching Strategy

```
main branch:
├── terraform apply auto dari PR yang approved
├── Production infrastructure

feature/infrastructure:
├── Develop new infrastructure
├── PR ke main
└── Review dan approve
```

### 2. GitOps Workflow

```yaml
# .github/workflows/terraform.yml

name: Terraform

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  terraform:
    runs-on: ubuntu-latest

    steps:
      - uses: actions/checkout@v4

      - name: Setup Terraform
        uses: hashicorp/setup-terraform@v2
        with:
          terraform_version: 1.6.6

      - name: Terraform Init
        run: terraform init

      - name: Terraform Format
        run: terraform fmt -check

      - name: Terraform Plan
        if: github.event_name == 'pull_request'
        run: terraform plan -no-color

      - name: Terraform Apply
        if: github.event_name == 'push' && github.ref == 'refs/heads/main'
        run: terraform apply -auto-approve
        env:
          AWS_ACCESS_KEY_ID: ${{ secrets.AWS_ACCESS_KEY_ID }}
          AWS_SECRET_ACCESS_KEY: ${{ secrets.AWS_SECRET_ACCESS_KEY }}
```

## Best Practices

### 1. Use Modules

```hcl
# ❌ BAD: All in one file
resource "aws_instance" "web1" { ... }
resource "aws_instance" "web2" { ... }
resource "aws_instance" "web3" { ... }

# ✅ GOOD: Use modules
module "web_servers" {
  source = "./modules/ec2_cluster"
  instances = 3
}
```

### 2. Separate Environments

```
infrastructure/
├── prod/
│   ├── main.tf
│   ├── variables.tf
│   └── terraform.tfvars
├── staging/
│   ├── main.tf
│   ├── variables.tf
│   └── terraform.tfvars
└── modules/
    └── ...
```

### 3. Remote State with Locking

```hcl
terraform {
  backend "s3" {
    bucket         = "my-terraform-state"
    key            = "prod/terraform.tfstate"
    region         = "ap-southeast-1"
    encrypt        = true
    dynamodb_table = "terraform-locks"
  }
}
```

### 4. Sensitive Variables

```hcl
# ❌ BAD: Plain text passwords
variable "db_password" {
  default = "my-secret-password"
}

# ✅ GOOD: Use sensitive flag dan environment variable
variable "db_password" {
  description = "Database password"
  type        = string
  sensitive   = true
}

# Di terraform.tfvars, reference environment variable:
# db_password = var.db_password
# Set dengan: export TF_VAR_db_password="my-secret-password"
```

### 5. State Isolation

```hcl
# Separate state per environment
terraform {
  backend "s3" {
    key = "prod/terraform.tfstate"  # Production
    # key = "staging/terraform.tfstate"  # Staging
  }
}
```

## Troubleshooting

### Error: Provider Not Initialized

```bash
# Error:
# Error: Required plugin was not available

# Solusi:
terraform init
```

### Error: State Lock

```bash
# Error:
# Error: Error acquiring the state lock

# Solusi:
# Cek siapa yang lock
terraform force-unlock LOCK_ID

# Atau tunggu sampe proses lain selesai
```

### Error: Plan/Apply Mismatch

```bash
# Error:
# Error: Provider produced inconsistent result

# Solusi:
terraform plan -refresh=true
terraform apply -refresh=true
```

```
| 2. Declarative | Specify what, not how |
| 3. State management | Track deployed resources |
| 4. Provider ecosystem | Hampir semua providers support |
| 5. Large community | Dokumentasi dan help readily available |
```

**The Takeaway:**

Lo bisa setup server complex dengan thousands of resources dalam minutes, tinggal `terraform apply`. Dan kalo ada yang salah? `git checkout` ke versi sebelumnya, `terraform apply`, done.

Terraform itu investasi yang worth it. Initial learning curve ada, tapi long-term benefits jauh lebih besar.

Giliran lu, mulai dari one small piece. Misalnya VPC atau EC2 instance. Once lo comfortable, expand dari situ.
