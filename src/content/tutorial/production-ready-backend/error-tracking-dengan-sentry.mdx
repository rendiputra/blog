## Kenapa Sentry?

Oke, lo mungkin thinking | "Gue bisa aja pake console.log() atau bikin custom logger."

Mari gue tunjukin kenapa itu nggak cukup:

```
console.log() Problems:
| Nggak keliatan kalau lo nggak monitoring terminal
| Ilang kalau server di-restart
| Nggak ada context (user, request ID, environment)
| Nggak ada stack trace yang proper
| Nggak ada grouping (1000 same error = 1000 lines)
| Nggak ada alerting

Sentry Benefits:
| Auto-capture semua unhandled exception
| Full stack trace dengan source code context
| User context (lo tau error ini dari user mana)
| Request context (lo tau request apa yang trigger)
| Error grouping (similar errors di-group)
| Alerting (Telegram, Slack, Email)
| Performance monitoring
| Release tracking
```

## Node.js: Setup Sentry

Oke, sekarang masuk ke kode. Gue assume lo pake Express.js, tapi konsepnya sama buat framework lain.

### Basic Setup

```javascript
// sentry.js | Sentry configuration
const Sentry = require('@sentry/node');

// Initialize Sentry
Sentry.init({
  dsn: process.env.SENTRY_DSN,

  // Environment
  environment: process.env.NODE_ENV || 'development',

  // Release tracking (auto-detect dari git)
  release: process.env.npm_package_version,

  // Sample rate | 1.0 = capture semua, 0.1 = 10%
  tracesSampleRate: 1.0,

  // Enable debug mode di development
  debug: process.env.NODE_ENV === 'development',

  // Add request context secara otomatis
  integrations: [
    new Sentry.Integrations.Http({ tracing: true }),
    new Sentry.Integrations.Express({ app: require('express') }),
    new Sentry.Integrations.Mongo(),
    new Sentry.Integrations.Postgres(),
  ],
});

module.exports = Sentry;
```

### Integrate dengan Express

```javascript
// app.js | Express app dengan Sentry
const express = require('express');
const Sentry = require('./sentry');
const myApp = require('./routes');

const app = express();

// Sentry request handler | taruh di TOP of middleware stack
app.use(Sentry.Handlers.requestHandler());

// Health check (biasanya sebelum Sentry capture)
app.get('/health', (req, res) => {
  res.json({ status: 'ok' });
});

// Lo mau exclude health check dari error tracking?
// app.get('/health', Sentry.Handlers.ignoreFunction, (req, res) => { ... });

// Body parser
app.use(express.json());

// Routes
app.use('/', myApp);

// Sentry error handler | taruh di BOTTOM of middleware stack
app.use(Sentry.Handlers.errorHandler());

// Custom error handler (optional)
app.use((err, req, res, next) => {
  // Lo masih mau capture error di Sentry
  // atau handle custom logic

  // Log manual kalau perlu
  console.error('Custom error:', err);

  res.status(err.status || 500).json({
    error: err.message || 'Internal Server Error',
    // Jangan kasih stack trace di production response!
  });
});

// Start server
const PORT = process.env.PORT || 3000;
app.listen(PORT, () => {
  console.log(`Server running on port ${PORT}`);
});
```

### Capture Error Secara Manual

Kadang lo nggak throw error | lo cuma mau log sesuatu ke Sentry:

```javascript
// Contoh: Validation error yang bukan fatal
app.post('/checkout', async (req, res) => {
  try {
    const { userId, items } = req.body;

    if (!items || items.length === 0) {
      // Lo mau catat ini sebagai warning, bukan error
      Sentry.captureMessage('Checkout attempt with empty cart', {
        level: 'warning',
        tags: { feature: 'checkout' },
        extra: { userId },
      });

      return res.status(400).json({ error: 'Cart is empty' });
    }

    // Continue normal flow...
    const result = await processCheckout(userId, items);
    res.json(result);

  } catch (error) {
    // Error yang actual fatal
    Sentry.captureException(error, {
      extra: {
        userId: req.body.userId,
        items: req.body.items,
      },
    });

    res.status(500).json({ error: 'Checkout failed' });
  }
});
```

### Tambahkan User Context

Ini yang penting | biar lo tau error ini dari user mana:

```javascript
// Middleware untuk set user context
app.use((req, res, next) => {
  if (req.user) {
    // Set user context ketika ada authenticated user
    Sentry.setUser({
      id: req.user.id,
      email: req.user.email,
      username: req.user.username,
    });
  }

  // Add custom context
  Sentry.setTag('api_version', req.headers['x-api-version']);

  next();
});
```

Sekarang setiap error yang ke-capture bakal include info:
- User ID dan email
- Request ID
- API version
- Full stack trace

## Go: Setup Sentry

Sekarang untuk Go developer. Setup-nya sedikit beda karena Go use context.

### Install SDK

```bash
go get github.com/getsentry/sentry-go
```

### Basic Setup

```go
// sentry.go
package main

import (
    "log"
    "os"

    "github.com/getsentry/sentry-go"
)

func InitSentry() {
    err := sentry.Init(sentry.ClientOptions{
        Dsn: os.Getenv("SENTRY_DSN"),

        // Environment
        Environment: os.Getenv("GO_ENV"),

        // Release (from git)
        Release: getGitCommit(),

        // Sample rate | 1.0 = capture semua
        TracesSampleRate: 1.0,

        // Enable debug kalau di development
        Debug: os.Getenv("GO_ENV") == "development",

        // Attach stack trace
        AttachStacktrace: true,

        // Server name untuk identifikasi
        ServerName: os.Hostname(),
    })

    if err != nil {
        log.Fatalf("Sentry initialization failed: %v", err)
    }
}

func getGitCommit() string {
    // Bisa ambil dari git rev-parse HEAD
    // Atau dari environment variable yang di-set di CI/CD
    return os.Getenv("GIT_COMMIT")
}
```

### Setup dengan Gin Framework

```go
// main.go
package main

import (
    "fmt"
    "net/http"

    "github.com/gin-gonic/gin"
    "github.com/getsentry/sentry-go"
)

func main() {
    InitSentry()

    // Setup Gin
    r := gin.Default()

    // Sentry middleware
    r.Use(sentryMiddleware())

    // Routes
    r.GET("/health", healthCheck)
    r.POST("/checkout", checkout)

    r.Run(":8080")
}

func sentryMiddleware() gin.HandlerFunc {
    return func(c *gin.Context) {
        // Inject Sentry context ke request
        sentry.WithScope(func(scope *sentry.Scope) {
            scope.SetRequest(c.Request)

            // Set user kalau ada
            if userID, exists := c.Get("user_id"); exists {
                scope.SetUser(sentry.User{
                    ID: fmt.Sprintf("%v", userID),
                })
            }

            c.Set("sentry_scope", scope)
        })

        c.Next()
    }
}

func healthCheck(c *gin.Context) {
    c.JSON(http.StatusOK, gin.H{"status": "ok"})
}

func checkout(c *gin.Context) {
    var req CheckoutRequest
    if err := c.ShouldBindJSON(&req); err != nil {
        c.JSON(http.StatusBadRequest, gin.H{"error": err.Error()})
        return
    }

    // Process checkout
    result, err := processCheckout(req)
    if err != nil {
        // Capture error
        if scope, exists := c.Get("sentry_scope"); exists {
            scope.(*sentry.Scope).CaptureException(err)
        } else {
            sentry.CaptureException(err)
        }

        c.JSON(http.StatusInternalServerError, gin.H{"error": "checkout failed"})
        return
    }

    c.JSON(http.StatusOK, result)
}
```

### Manual Error Capture

```go
// Capture error dengan context
func someFunction() {
    defer sentry.Recover()

    result, err := riskyOperation()
    if err != nil {
        sentry.WithScope(func(scope *sentry.Scope) {
            scope.SetLevel(sentry.LevelError)
            scope.SetTag("operation", "risky_operation")
            scope.SetExtra("retry_count", 3)
            scope.CaptureException(err)
        })
    }
}
```

// webhook-handler.js | Cloudflare Worker atau Express endpoint
app.post('/webhooks/sentry', async (req, res) => {
  const { alert_name, error_level, error_message, error_url } = req.body;

  // Kirim ke Telegram
  const telegramMessage = `
🚨 *Sentry Alert*

*Alert:* ${alert_name}
*Level:* ${error_level}
*Message:* ${error_message}
*URL:* ${error_url}

Time: ${new Date().toISOString()}
  `.trim();

  await fetch(`https://api.telegram.org/bot${process.env.TELEGRAM_BOT_TOKEN}/sendMessage`, {
    method: 'POST',

      chat_id: process.env.TELEGRAM_CHAT_ID,
      text: telegramMessage,

## Best Practices

### 1. Jangan Capture Sensitive Data

```javascript
// ❌ Bad: Kebocoran data sensitif
Sentry.configureScope((scope) => {
  scope.setExtra('password', req.body.password); // NO!
  scope.setExtra('credit_card', req.body.cardNumber); // DEFINITELY NO!
});

// ✅ Good: Sensor data sensitif
Sentry.configureScope((scope) => {
  scope.setExtra('request_body', {
    email: req.body.email,
    // Password di-sensor otomatis oleh SDK
  });
});
```

Lo bisa set `sendDefaultPii: false` di config buat auto-censor.

### 2. Sample Error Rates

Lo nggak mau Sentry overwhelms pas traffic tinggi:

```javascript
Sentry.init({
  dsn: process.env.SENTRY_DSN,

  // Kalau traffic tinggi, sample 10% error aja
  tracesSampleRate: 0.1,
  profilesSampleRate: 0.1,

  // Untuk high-volume endpoints
  sampleRate: 0.1, // Capture 10% sampled errors
});
```

### 3. Environment-Specific Config

```javascript
// sentry.js
const Sentry = require('@sentry/node');

Sentry.init({
  dsn: process.env.SENTRY_DSN,
  environment: process.env.NODE_ENV,

  // Only capture source maps dan full context di production
  attachStacktrace: process.env.NODE_ENV === 'production',

  // Debug mode cuma di development
  debug: process.env.NODE_ENV === 'development',

  // Lower sample rate di production
  tracesSampleRate: process.env.NODE_ENV === 'production' ? 0.1 : 1.0,
});
```

### 4. Release Tracking

Setup release tracking biar lo tau error ini muncul setelah deploy mana:

```bash
# Di CI/CD pipeline (GitHub Actions example)
- name: Deploy
  run: |
    # Deploy code
    ./deploy.sh

    # Tell Sentry which release
    npx sentry-cli releases new $GITHUB_SHA
    npx sentry-cli releases files $GITHUB_SHA
    npx sentry-cli releases deploys $GITHUB_SHA new --env production
```
